# CarRental — règles du projet

## Commandes
- Outils locaux (dotnet-ef) : `dotnet tool restore`
- Dépendances locales (SQL Server 2022 sur `localhost,14333`, Azurite) : `docker compose up -d`
- Build : `dotnet build -warnaserror`
- Tests : `dotnet test` (les cinq projets ; Docker requis pour l'intégration et l'E2E, ou des serveurs déjà démarrés désignés par `CARRENTAL_TEST_SQL` et `CARRENTAL_TEST_STORAGE`, voir `tests/Shared/TestInfrastructure.cs`)
- Format : `dotnet format` (la CI vérifie `dotnet format --verify-no-changes`)
- Lancer : `dotnet run --project src/CarRental.Web` (https://localhost:7180 ; migrations et données de démonstration appliquées au démarrage en développement)
- Migration : `dotnet ef migrations add <Name> -p src/CarRental.Infrastructure -s src/CarRental.Web -o Persistence/Migrations`
- Fusion des `.resx` : pilote `tools/git/merge-resx.mjs` (fusion à trois voies des entrées par clé), à déclarer une fois par clone : `git config merge.resx.driver "node tools/git/merge-resx.mjs %O %A %B"`.
- Avant chaque commit : `dotnet format`, `dotnet build -warnaserror` et `dotnet test` verts ; commits Conventional Commits en anglais.

## Architecture
- Monolithe modulaire .NET 10 ; modules dans Application/<Module> ; aucune référence directe entre entités de modules.
- Vitrine en rendu statique ; /admin en InteractiveServer avec MudBlazor.
- Mémoire (ADR-0068) : une instance B1 (1 cœur, 1,75 Go) ; GC station de travail concurrent + `ConserveMemory`, circuits Blazor bornés (`Blazor:*`), corps de requête limité par Kestrel, caches bornés (cache mémoire à taille maximale, purge des instantanés de disponibilité) ; lectures en `AsNoTracking`, aucune liste non paginée vers le client.
- Événements de domaine → outbox → Hangfire. L'outbox est un mécanisme d'infrastructure : son administration (`/admin/outbox`, service `OutboxAdministrationService`), sa purge et son entrée de santé vivent dans `Infrastructure/Outbox`, seule exception à la recette des cas d'usage (ADR-0028).
- Santé : chaque entrée enregistrée est évaluée chaque minute et publiée (`carrental.health.status`, `HealthStatusPublisher`), alertée par `infra/modules/alerts.bicep` (ADR-0060) ; une nouvelle entrée (Degraded, jamais Unhealthy) est couverte sans toucher l'infrastructure. Exploitation : `docs/runbook.md` ; revue de sécurité : `docs/securite/`.
- Couches : `Domain` (aucune dépendance) ← `Application` (cas d'usage, ports, EF Core sans fournisseur) ← `Infrastructure` (EF Core SQL Server, Identity, Hangfire, Blob, ACS) ← `Web` (hôte, composants, composition). Vérifié par `tests/CarRental.Architecture.Tests`.
- Modules : Referential, Identity, Fleet, Pricing, Bookings, Customers, Payments, Billing, Cash, Channels, Messaging, Reporting, Accounting. Pour chacun :
  - `src/CarRental.Domain/<Module>/` : agrégats, objets valeur, événements, `<Module>Errors` ;
  - `src/CarRental.Application/<Module>/<Module>Module.cs` : `Add<Module>Module()`, appelé par `AddApplication()` ;
  - `src/CarRental.Application/<Module>/Contracts/` : seule surface visible des autres modules (`I<Module>Queries`, DTO, identifiants) ;
  - `src/CarRental.Infrastructure/Persistence/Configurations/<Module>/` : configurations EF ; schéma SQL `<module>` (`Schemas`).
- Noyau commun : `Domain/Common` (`Result`, `Error`, `Entity`, `AggregateRoot`, `Money`, `Period`, `AcrissCode`, `TunisTime`, `DocumentNumber`) et `Application/Common` (`IAppDbContext`, `IUnitOfWork`, `IAvailabilityLock`, `IDocumentNumberGenerator`, `IOutbox`, `IUserContext`, `IAuditTrail`, `IDocumentAccessLog`, `IFileStorage`, `IEmailQueue`, `IDataSeeder`, `IRecurringJob`).
- Plateforme multi-agences (ADR-0067) : une seule application et une seule base pour toutes les agences, chaque ligne d'une agence porte `AgencyId`. Le **support** (rôle `Support`, permissions de la zone Plateforme `platform.agencies`, `jobs.dashboard`, `outbox.manage`, jamais accordées à un membre d'une agence) crée les agences (`/admin/platform`), leur adresse de vitrine (`Agency.Slug`) et leurs modules, invite leur gérant, puis entre dans une agence pour y travailler ; le personnel n'appartient qu'à une agence (`ApplicationUser.AgencyId`). Modules activables par agence (`AgencyModules` : vitrine, WhatsApp, canaux, caisse, sinistres et amendes, pré-comptabilité, rapports ; WhatsApp et canaux fermés à la création), le cœur (flotte, tarifs, dossiers, clients, paiements, factures, utilisateurs, paramètres) toujours présent.
- Domaine propre d'une agence (ADR-0069) : le support rattache des noms d'hôte à une agence (`AgencyDomain`, un principal, les autres redirigent ; uniques sur la plateforme, jamais un nom de la plateforme `IPlatformHosts`) ; `AgencyHostMiddleware` (avant la localisation et le routage) réécrit `https://www.agence.tn/fr/…` en `/{agence}/fr/…`, sauf les adresses de la plateforme (mots réservés, `/api/channels`, `/api/openapi`, fichiers statiques) ; les liens de la vitrine, des e-mails et du bot n'ont alors aucun segment d'agence (`PublicSiteAgency.SlugOf(context)` vide, `AgencySummary.LinkSlug`, `PrimaryHost`), l'adresse canonique et le plan du site pointent sur l'hôte principal ; le retour de Clic to Pay (hôte de la plateforme) renvoie sur l'hôte de l'agence.
- Décisions : `docs/adr` (0011 à 0020 pour le socle ; 0028 exploitation de l'outbox et requêtes fractionnées, 0029 paramètres, permissions par utilisateur et accessibilité du back office ; 0067 multi-agences ; 0069 domaines propres). Infrastructure Azure : `infra/README.md`.

## Invariants (ne jamais casser)
- Pas de chevauchement d'affectation véhicule (tampon inclus) ; capacité par catégorie jamais dépassée.
- Écriture de disponibilité uniquement sous sp_getapplock('availability:{categoryId}').
- Devis figé, factures immuables (correction par avoir), paiement confirmé par getOrderStatusExtended uniquement.
- Money en decimal(18,3) TND, arrondi AwayFromZero ; temps via TimeProvider, UTC en base, Africa/Tunis pour les règles.
- Pièces d'identité : accès autorisé et journalisé uniquement.
- Le bot ne crée jamais de dossier et ne cite que des prix venant des outils.
- Journal d'audit en ajout seul : jamais de mise à jour ni de suppression (intercepteur et déclencheurs SQL).
- Numéros `LOC`, `FAC`, `AV` sans trou dans chaque agence : `IDocumentNumberGenerator.NextAsync(agence, type, année)` dans la transaction, jamais de séquence SQL ; un numéro n'est unique que dans son agence, toute recherche par numéro se fait dans une agence.
- Une agence ne voit jamais les données d'une autre : filtre de requête nommé `Agency` sur toute entité d'agence, levé seulement par une requête de la plateforme voulue et relue (`IgnoreQueryFilters([QueryFilters.Agency])`, jamais `IgnoreQueryFilters()` nu) ; le pipeline d'enregistrement refuse (`AgencyBoundaryException`) une ligne d'une autre agence, un changement d'agence, une donnée d'agence sans agence ; `ExecuteUpdate`/`ExecuteDelete` (seul le filtre s'y applique) et le SQL brut (ni l'un ni l'autre) échappent à ce garde : leur prédicat dit lui-même l'agence visée.
- Aucun fait financier daté dans un mois clos : l'écrivain appelle `IAccountingPeriods.EnsureOpenAsync(agence, jour)` dans son unité de travail (verrou partagé `accounting:period:{agence}:{yyyy-MM}`, exclusif pour la clôture et la réouverture) ; une caution ne touche jamais un compte de classe 7.

## Conventions
- Code, commits et commentaires en anglais ; textes UI en .resx (fr, en ; ar prévu).
- Result/Result<T> pour les erreurs métier ; pas d'exception de contrôle de flux.
- Tests d'abord pour le domaine ; test de référence du prix toujours vert.
- Formats partenaires non confirmés : interface + faux + TODO(spec), jamais d'invention.
- Codes d'erreur stables `module.objet.raison` ; texte affiché par la ressource `Error.<code>` (fr et en).
- Identifiants `Guid.CreateVersion7()` (`Entity.NewId()`), propriétés à setter privé, fabriques statiques qui renvoient `Result<T>`.
- Avertissements traités comme des erreurs ; un `NoWarn` ciblé seulement s'il est justifié dans `Directory.Build.props` ou `.editorconfig`.
- Versions des paquets uniquement dans `Directory.Packages.props` ; pas de dépendance payante ou à licence ambiguë.
- Aucun secret dans le dépôt : valeurs de développement marquées comme telles avec un commentaire `gitleaks:allow` ; secrets Azure dans le Key Vault (`Section--Clé`), identité managée partout, jamais de clé de compte (liens temporaires = SAS de délégation d'utilisateur).
- Migrations rétrocompatibles : elles s'appliquent (bundle) avant le déploiement du nouveau code ; ajouter puis supprimer en deux temps.
- Journaux : aucune portée exportée (`IncludeScopes` reste faux : la portée de requête porte le chemin et ses jetons) ; un chemin journalisé passe par `SecretPaths.Redact`.
- **Facturation** : document émis immuable (correction = avoir) ; numéro FAC/AV pris en dernier dans l'unité de travail ; une facture par dossier et par type (verrou `billing:booking:{id}` + index unique) ; montants repris du devis courant et des frais de retour, TVA par taux comme le moteur de prix, timbre hors TVA ; TTN, PDF `invoices/{année}/{numéro}-{id}.pdf` (jamais réécrit : conteneur immuable en production) et e-mail suivent par l'outbox, une fois chacun (ADR-0057 à 0059).
- **Pré-comptabilité** : journaux VT/AC/BQ/CA/OD générés à la demande depuis les contrats des autres modules, figés à la clôture ; un fait figé puis changé passe en correction dans le mois ouvert ; nouveau type d'opération = clé d'`AccountingMappingCatalog` + compte par défaut + libellé `Mapping.<clé>` (test) ; exports par `IJournalExporter` (format générique, formules neutralisées) ; dépenses `DEP-{année}-{séquence}` sous `cash:expense-number:{agence}:{année}`, justificatifs dans `invoices/expenses/…`, jamais réécrits (ADR-0063 à 0065).
- **Multi-agences** (ADR-0067) : l'acteur (`IUserContext`, `UserContextSnapshot`) porte l'agence de l'opération (`AgencyId`) ou le travail pour toutes les agences (`AllAgencies` : support hors agence, système) ; un service lit l'agence dans `IUserContext.AgencyId` (ou dans la donnée qu'il traite), jamais « la première agence » ; une opération limitée à une agence sans agence ne voit rien. Toute portée créée à la main (`CreateAsyncScope`) initialise son acteur (`ScopedUserContext.Initialize(UserContextSnapshot.System("system:…", agencyId: …))`), sinon elle ne voit rien. Les index uniques métier sont par agence (`(AgencyId, …)`) ; restent uniques sur la plateforme, avec un commentaire, les clés de route, de partenaire ou de secret (`Agency.Slug`, `Channel.Code`, identifiants Meta, empreintes de jetons). Une tâche de fond ou un gestionnaire de l'outbox donne à ce qu'il crée l'agence de la donnée traitée, ne prévient que le personnel de cette agence et passe les agences suspendues ou dont le module est fermé (`IAgencyDirectory.HasModuleAsync`). Ce qu'une nouvelle agence reçoit à sa création (plan de comptes, base de connaissances…) : `IAgencyInitializer` déclaré par `services.AddAgencyInitializer<T>()`.

## Recettes
- **Entité ou agrégat** : classe `sealed` dans `Domain/<Module>` héritant d'`AggregateRoot` (ou `Entity`), constantes de longueur, invariants vérifiés dans les méthodes, événements `sealed record … : IDomainEvent` levés par `Raise(...)`, `ISoftDeletable` si suppression logique. Configuration `internal sealed class XConfiguration : IEntityTypeConfiguration<X>` dans `Persistence/Configurations/<Module>/` : `builder.ToTemporalTable("Xs", Schemas.<Module>)` pour un historique (sinon `ToTable`), longueurs, index ; `.IsAuditSensitive()` sur une donnée sensible. L'entité dit à qui ses lignes appartiennent : `IAgencyOwned` (donnée d'une agence, enfants compris, qui reçoivent l'agence de leur racine à la création), `IAgencyShared` (valeur commune `null` ou propre à une agence) ou `IAgencyOrPlatform` (enregistrement d'une agence ou de la plateforme), sinon elle figure dans la liste des tables de la plateforme de `TenancyConventionTests` ; `AgencyId` ne change jamais, index commençant par `AgencyId` pour les listes d'une agence. Puis migration (rattrapage des lignes existantes en SQL écrit à la main dans `Persistence/Migrations/Backfill/`) et tests (domaine, intégration, cloisonnement).
- **Cas d'usage** : service `sealed` dans `Application/<Module>`, enregistré dans `<Module>Module.cs` ; vérifie `IUserContext.HasPermission(...)` ; écrit dans `IUnitOfWork.ExecuteAsync(...)` dès qu'il y a verrou, numéro ou plusieurs agrégats ; l'opération est rejouée en entier après une panne passagère : charger les données dans le délégué.
- **Écriture de disponibilité** : prendre le ou les verrous de catégorie (`IAvailabilityGuard`, identifiants croissants) avant le numéro `LOC` : la ligne du compteur reste verrouillée jusqu'au commit, l'ordre inverse interbloque (ADR-0025, ADR-0032).
- **Effet de bord** (e-mail, WhatsApp, canal) : jamais direct ; `IOutboxHandler<TEvent>` idempotent, déclaré par `services.AddOutboxHandler<TEvent, THandler>()` ; e-mail par `IEmailQueue`.
- **Tâche récurrente** : `IRecurringJob` (`static JobId`, `static CronExpression`, heure de Tunis), déclarée par `services.AddRecurringJob<T>()` ; elle tourne pour toutes les agences et traite de préférence chaque agence dans une portée limitée à elle (`UserContextSnapshot.System(nom, agencyId: …)`).
- **Données initiales** : `IDataSeeder` idempotent, `Stage` `Reference` (tous les environnements) ou `Demo` (seulement si `Seed:Demo`), `Order` : 100 identité, 200 référentiel, 300 utilisateurs de démonstration, 400 flotte, 500 tarifs, 600 clients, 700 dossiers, 800 finance ; `services.AddDataSeeder<T>()` ; un jeu de démonstration s'exécute comme `system:seed` (toutes agences) et donne à chaque donnée son agence (« Agence Démo Tunis », « Agence Démo Sousse »).
- **Paramètre métier** : définition par une fabrique de `SettingDefinitions` (`Duration`, `Number`, `Amount`, `Boolean`, `WholeNumber`, `Text`, `TimeRange` ; ses bornes règlent l'éditeur de l'écran) dans `WellKnownSettings` ou dans les `Contracts` du module (`services.AddSettingDefinitions(...)` dans `Add<Module>Module()`), `.PlatformOnly()` si aucune agence ne doit la remplacer ; lecture par `ISettingsReader` (valeur de l'agence, sinon de la plateforme, sinon par défaut) ; libellé `Setting.<clé>.Label`, aide `Setting.<clé>.Help` et titre `Group.<premier segment>` dans `Resources/Admin/Settings/SettingLabels(.en).resx` (test d'architecture ; sans libellé, l'écran affiche la clé) ; modifiable dans `/admin/settings` (validation par la définition, audit, cache des disponibilités vidé à chaque changement).
- **Permission** : constante et entrée du catalogue dans `Permissions` (et ce qu'elle inclut : gérer inclut consulter), préréglages dans `RolePresets` (fermés par inclusion : test), matrice dans `RolePresetTests`, libellé `Permission.<nom>` dans `Resources/Admin/Identity/PermissionResources(.en).resx` (test) ; un gérant confie des permissions supplémentaires à un utilisateur de son agence dans `/admin/users` (revendications de l'utilisateur, auditées, appliquées dès sa requête suivante sans nouvelle connexion) ; une permission de la zone Plateforme n'appartient qu'au rôle `Support` et n'est jamais accordée à un membre d'une agence.
- **Écran du back office** : `Components/Admin/Pages/<Module>/XPage.razor`, `@page "/admin/..."` et `@attribute [HasPermission(Permissions.X)]` (mise en page et double authentification viennent de `_Imports.razor`) ; remplace l'écran « À venir » de `Admin/Pages/Placeholders` ; entrée de menu dans `AdminNavigation` avec la même permission (test) ; titre `<MudText Typo="Typo.h4" HtmlTag="h1">` ; appels aux services par `IOperationRunner.RunAsync<TService, TResult>(...)`, jamais par injection directe (portée du circuit ; aucun type EF ni de persistance dans un composant : test) ; textes dans `Resources/Admin/...resx` (mêmes clés en fr et en).
- **Accessibilité du back office** (WCAG 2.2 AA, axe sans violation critique ou sérieuse) : la palette `AdminTheme` tient 4,5:1 partout, donc `Color.Success/Warning/Error/Info/Tertiary` s'utilisent sans contournement sur boutons, puces et `MudAlert` (le bloc `Notice` des clients reste possible) ; tableau paginé : `<MudTable RowsPerPage="25">` + `<PagerContent><AdminTablePager /></PagerContent>` (liste des tailles nommée ; `MudTablePager` seul seulement avec `HideRowsPerPage="true"` : test) ; chaque champ a un `Label` (un `MudSelect` nomme sa liste par son `Label`), chaque bouton icône un `aria-label` ; le bouton de titre vide d'un `MudDatePicker` sans valeur est masqué par `admin.css` ; les textes propres à MudBlazor (pagination, calendriers, dialogues…) viennent de `Resources/Admin/MudBlazor` via `MudBlazorLocalizer` ; référence vivante et test : `/admin/ui-gallery` (absente en production) ; test E2E d'un écran : `BackOfficeSession.SignInAsync`, `WaitUntilInteractiveAsync` (attribut `data-interactive` du `main`) puis `AssertNoSeriousAxeViolationAsync`.
- **Page publique** : `Components/Public/Pages`, `@page "/{agency}/{culture:length(2)}/..."` (le premier segment est l'adresse de la vitrine de l'agence, ADR-0067), hérite de `PublicPageBase` (agence de la vitrine `SiteAgency`, liens par `PublicRoutes.PathFor(Slug, …)` où `Slug` est le premier segment des liens : l'adresse de la vitrine sur l'hôte de la plateforme, vide sur le domaine propre de l'agence, ADR-0069 ; dans un point d'accès, `PublicSiteAgency.SlugOf(context)` ; jamais `AgencySummary.Slug` dans un lien), rendu statique sans mode interactif, `PageTitle`, description et `hreflang` ; CSS écrite à la main dans `wwwroot/css/site.css` (variables, propriétés logiques, mobile d'abord), aucun MudBlazor ; textes dans `Resources/Public`.
- **Fichiers** : `IFileStorage` et `FileContainers` (conteneurs privés) ; pièce d'identité toujours avec `IDocumentAccessLog`.
- **Point d'accès** : autorisé, ou anonyme avec une politique de limitation de débit ; sinon l'ajouter, justifié, à `Security/EndpointInventoryTests`. Un fichier à données personnelles répond `no-store, private`, sans `ETag` ; une adresse de retour lue dans la requête passe par `LocalUrls.IsLocal`.

## Tests
- `tests/CarRental.Domain.Tests` (objets valeur, agrégats, propriétés FsCheck), `tests/CarRental.Application.Tests` (services avec `Fakes/`), `tests/CarRental.Architecture.Tests` (couches, modules, conventions), `tests/CarRental.Integration.Tests` et `tests/CarRental.E2E.Tests`.
- Intégration et E2E : un fixture d'assembly démarre SQL Server et Azurite (Testcontainers) et l'application réelle (`tests/Shared/CarRentalAppFactory.cs`, environnement `Testing`). Une classe de test reçoit `IntegrationHost` (ou hérite de `BrowserTest`) par son constructeur ; `host.CreateScope(acteur)` pour appeler un service, `host.CreateClient()` et `Support/HttpSignIn` pour HTTP, `Totp.Compute(...)` pour le code. Tests en parallèle : données uniques par test — un compte par test (`Support/TestStaff.CreateAsync` en intégration, `Support/BackOfficeSession.NewStaffAsync` en E2E), une agence par test pour ses valeurs de paramètres, et les paramètres propres aux tests (`tests/Shared/TestSettings`, clés `tests.*`) pour changer une valeur de la plateforme.
- E2E : Chromium installé par le fixture ; traces et captures des échecs dans `E2E_ARTIFACTS_DIR` (sinon `bin/.../e2e-artifacts`) ; axe sans violation critique ou sérieuse (`BackOfficeSession.AssertNoSeriousAxeViolationAsync`, après `WaitForOpenPopoverAsync` ou `WaitForOpenDialogAsync` : axe mesurerait le contraste d'un texte en cours d'apparition) ; 390 px de large par défaut.
- Acteurs des tests (`tests/Shared/TestActors.cs`) : `TestActors.Staff(agence, rôle)` (personnel d'une agence), `Support()`, `Visitor(agence)`, `SystemFor(agence)` ; `Support/TestStaff.CreateAsync(host, rôle, agencyId: …)` puis `TestStaff.ActorAsync` pour un compte réel. - Filtrer : `dotnet test tests/CarRental.Integration.Tests --filter "FullyQualifiedName~ConcurrencyTests"`.
- Scénarios de bout en bout (`tests/*/Scenarios`, `docs/scenarios/journee-haute-saison.md`) : la journée de haute saison d'intégration tourne sur son propre hôte (`HighSeasonHost` : base dédiée, horloge `ScenarioClock` qui n'avance que vers l'avant, serveur Hangfire arrêté — une tâche se joue à son heure par `RunJobAsync(jobId)` —, sans données de démonstration) ; le scénario navigateur tourne dans une collection sans parallélisme, après les autres tests de navigateur. Filtrer : `--filter "FullyQualifiedName~Scenarios"`.
- Mois comptable simulé : `Integration.Tests/Accounting/AccountingMonthHost` (base propre, `SimulatedClock` réglable ; `IntegrationHost.Over(...)` réutilise les mondes des autres tests). En E2E, une agence créée par un test doit se trier après « Agence Démo Tunis ».
- Tests sans conteneur du web et de l'infrastructure dans `tests/CarRental.Architecture.Tests/{Security,Observability}` ; hôte à limites basses `Security/SecurityScenarioHost` (base dédiée).
- Un test de continuité des numéros de l'année verrouille d'abord la ligne du compteur (`infra.DocumentCounters WITH (UPDLOCK, HOLDLOCK)`) ; les dossiers fabriqués à la main prennent une année hors de l'année courante ; en E2E, avant axe, attendre la fin des transitions d'un bouton tout juste activé et fermer les notifications (`BackOfficeSession.CloseSnackbarsAsync`) plutôt que d'attendre qu'elles disparaissent.
